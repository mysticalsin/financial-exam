# Financial assessment release addendum

This checklist covers the candidate and recruiter experience from public practice through recruitment record erasure. The design uses one EU R2 object for each assessment payload. An EU Durable Object serializes operations and schedules cleanup. The public preview may operate worldwide. Real recruitment opens only for approved recruiting countries and authorized staff.

## Evidence from the planning review

The Worker checks the invitation independently of the browser cookie, grades on the server and checks the record cutoff before returning a payload. The browser already strips invitation fragments and checks a history marker before resuming. During this review the session-read API still selected an attempt by cookie alone, write requests could omit the expected reference, and the live switch accepted a CLI token in place of staff Access configuration. The reviewer browser test used synthetic API responses. The deployment and screenshots preceding this addendum need a fresh check after changes. Each unchecked item below describes a proof still to obtain or record.

## Release evidence and limits

Record the three times separately for each retention test: invitation issue, result submission and application cutoff. A submitted result can be retrieved for up to 30 minutes after submission, capped at 60 minutes after invitation issue. A late submission can have a shorter review window. Verify the timestamp at which retrieval stops and independently check the storage object after alarm or sweep cleanup. Record provider logs, backups, or residual storage as separate questions for the contracted processor. Record reviewer identity tests as synthetic, denied anonymously or authenticated through the real identity provider as applicable.

Re-plan before opening recruitment if another candidate's paper can be retrieved, scoring can open with a missing notice or reviewer configuration, a result survives its application cutoff, or the hosted bytes differ from the tested package. Root owns the final release evidence. Luna owns application changes. The planning review made no source or deployment changes.

## Public full-length practice

Tony requested immediate access while the institution-specific recruitment setup is deferred. Publish a full 15-question practice assessment at the existing origin. A visitor can start, work through financial questions and receive a personal practice score without an invitation, account, country selector or recruiter. Use the source HTML’s eight foundation and seven applied questions, original choices and fixed figures on the first start and every retake. Shuffle only the order within each section and the positions of its answer options. Keep the private recruitment bank and individual recruiter reports outside the practice flow.

- [ ] **Practice API. Luna Handoff, 35 min.** Agree request and response fields with Luna Build first. A same-origin start call returns the assigned questions and choices, a challenge, server time and a 15-minute deadline. A grading call accepts that challenge and the candidate's selections. Seal the assigned paper’s grading information and expiry with authenticated encryption under its dedicated Worker secret. Apply the existing short-lived rate limiter. Return aggregate score, total and answered count. Reject invalid, expired and malformed submissions predictably. Public practice permits retakes. Keep its HTTP responses uncached and its application data out of cookies, browser storage, R2, Durable Objects and logs. Never put the signing secret in source, browser responses or handoff files.
- [ ] **Practice journey. Luna Build, 35 min, after API contract.** The public homepage offers “Start practice assessment” and explains the 15 questions, 15-minute limit, calculator use, private self-feedback and restart behavior on refresh. Retain invitation-specific instructions for real recruitment. Keep current answers in memory, allow changes and question review, and submit within the server deadline. On network failure preserve the current answers for retry while time remains. After expiry offer a new attempt. Show the personal score out of 15, a retake action and a clear or exit action. Clear displayed feedback on exit, refresh, retake or after 30 minutes. Send practice requests without credentials. Avoid a new identity, consent, email, country or staff setup step.
- [ ] **Operational proof. Root, 30 min, after both implementations.** Run deterministic grading tests for known answers, original practice-paper fidelity and recruitment-bank isolation, invalid selection/repeated question handling, challenge expiry and the 8/7 mix. In a fresh anonymous browser on the final hosted origin complete all 15 questions, revise an answer, see a score and retake the same original content with a fresh shuffle. Check keyboard navigation, timer, mobile financial tables, refresh and score clearing. Read the final site configuration and independent reviewer denials. Confirm the practice requests omit cookies, set none and use only same-origin endpoints. Trace the practice handlers to confirm there is no candidate-store write or score export. Record hosted version and test evidence. Provider-managed network metadata remains subject to the hosting account's policies.
